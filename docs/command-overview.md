# Commands run overview

The session overview counts distinct Bash and PowerShell command texts and their runs across the whole recording. Selecting a row opens its latest run; the adjacent disclosure lists repeated runs. Searches and WebFetch calls have separate totals and retain the same replay navigation, filtering, and recorded-outcome behavior.

## Classification

- A single, recognizable program keeps a program group. Executable paths and Windows `.exe`, `.cmd`, and `.bat` suffixes normalize to the program name.
- Inline Bash environment assignments can precede a single program, such as `MODE=test python check.py`. Assignment-only calls never become program names.
- Chains (including `cd … && …`), pipelines, multiline scripts, shell interpreters, control flow, command substitutions, and ambiguous input go to **Other commands**. The classifier deliberately does not guess a dominant command or rewrite the Other preview.
- Quotes protect literal operators in arguments: `python -c "print(1); print(2)"` is Python, and an ampersand in a quoted URL does not create a chain. Ordinary output redirects do not create another program. Unsupported syntax falls back conservatively.
- A command that spans lines is still one call when the newlines sit inside a quoted argument, follow a line continuation (`\` in Bash, a backtick in PowerShell), or belong to a heredoc or here-string body: `python -c "…"` around a multi-line script, `cat <<'EOF' > notes.txt` with its body, and `ls \` with its options on the next line are each listed under their program, with the recorded first line as the preview and a `+N lines` note. A newline outside those, as in `cd app` above `bun test`, separates calls, and the command goes to Other with a step row under each program.
- Program groups sit in categories: **Source control** (git, gh, and similar), **Files & text** (ls, cat, sed, grep, find, PowerShell item cmdlets, and similar), **Language & build tools** (known runtimes, compilers, package managers, and build/test tools), and **Network** (recognized HTTP clients, beside WebFetch calls). The allowlists live in `src/server/command-parts.ts`; unknown single programs remain visible under their own names above the categories. `wc` is a text utility, not a network tool, and shell `grep` and `rg` are text tools, not Searches.
- **Searches** keeps Grep, Glob, and WebSearch calls, distinguishing distinct searches from total calls. Every disclosure starts closed, in a fixed order; category counts and errors/stops remain visible while closed, and each category except Other names its programs with their run counts, the most run first, cut at whole names with the rest in the summary's accessible name. Program groups inside a category retain frequency ordering.

## Steps of multi-step commands

A command in Other commands is also listed, as a **step** row, under each program it calls at the top level, so a `gh` call inside `git fetch && gh pr checkout 143` is found under `gh` as well as under Other. `commandSteps()` in `src/server/command-parts.ts` splits the command on `&&`, `||`, `;`, `&`, `|`, newlines, and grouping, reading each segment as the single-command classifier does, with heredoc and here-string bodies, command and process substitutions, comments, and PowerShell expressions treated as opaque. Only the first stage of a pipeline is a step: `| jq`, `| grep -q`, and `| tail` never join a group. A wrapped call is read as the wrapper, so `sudo apt`, `xargs gh`, `env FOO=1 python`, and `bash -c "…"` are steps of `sudo`, `xargs`, `env`, and nothing, never of the program inside. A step joins a program's group when the program has a category or already has a group from a standalone command, so a chain never adds a group for `cd`, `echo`, or an unlisted tool; a program lists a command once, from its first call, and a step cannot open a group past the group limit. A command recorded by both shells with the same text has no steps.

The step row shows the call's own text from the program to the end of its line, after a muted `…` when the line has text before it, marked with a link icon in the gutter and a second line reading `step 2 of 3` for a one-line chain or `line 3 of 6` for a script. Its tooltip is the full recorded command; its accessible name says it is a step of a multi-step command also listed under Other commands and any other programs. The command's Other row keeps the recorded first line and `+N lines`, and names the groups that list its steps on a line of its own (`also under git, gh`, then `+N more` beyond two names, with the full list in its accessible name and tooltip). Selecting either row opens the same run, and the rail marks both. The marks follow the selected event however it was selected, from the rail, a find match, or a link, with an accent bar beside each row that opens it and `aria-current` on its button; a closed category whose rows include one carries the same bar on its summary. A selection made outside the rail opens the categories that hold its rows and scrolls the first into view when none is visible, while choosing a row in the rail leaves the rail where it is. A program's tally counts every row under it (`4 runs, 3 as steps · 1 error`), including step runs and their errors, so category totals overlap; the whole-recording line counts distinct commands and runs exactly, and the footnote says a step shows the outcome of its whole command.

## Faithful previews

Every Other row shows the original first non-empty line, capped for the sidebar, plus a count of additional non-empty lines. No setup fragments are moved below a guessed executable; a step preview is a verbatim substring of the recorded command. The tooltip contains the bounded original command; opening the run reveals the recorded call in full. WebFetch rows show the URL with their prompt beneath it and deduplicate by URL and prompt.

Classification never executes a command, expands a variable, resolves an alias, or fetches a URL. Outcome badges describe the recorded tool result, not inferred success of every command in a pipeline. Subagent activity is not included. Existing group, command, and run limits still apply; overflow programs join Other, and the overview reports when its lists are shortened. Whole-recording totals include all entries and calls. If the entry cap omits commands, searches, or fetches, their group tallies are marked **Listed:** and count all calls to the included entries only; step rows are not distinct entries for that check. Searches also states its whole-recording totals inside the disclosure when shortened. A capped run list or program-group overflow alone does not make group counts partial. This summary is computed from existing records and needs no index migration.
