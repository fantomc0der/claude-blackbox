# Architecture

claude-blackbox is a read-only, local-first browser for Claude Code transcripts.

## Boundaries

- `src/server`: Bun HTTP, incremental JSONL ingestion, SQLite FTS5 index, and local workspace preferences.
- `src/shared`: application data contracts, with no runtime or framework dependencies.
- `src/client`: Solid 2 components, URL-backed discovery state, and transcript presentation.
- `scripts`: Bun development runner and entirely synthetic demo recordings.
- `tests`: ingestion, search, API security, rendering helpers, and safe command quoting.
- `e2e`: Bun-run Playwright/Edge workflows, desktop viewport checks, and axe accessibility audits.

The server binds only to loopback. No transcript commands run, remote images load, telemetry is sent, or source files are changed. The derived index contains sensitive transcript data; keep its directory private. Workspace groups are reversible view preferences, not filesystem operations.

## Data flow

Discover JSONL files directly, including agent recordings. Index complete records using byte offsets and retain incomplete trailing writes for the next scan. Store provenance and raw records alongside searchable content. Reconcile changes and deletions, then notify clients with a single server-sent invalidation stream. Clients refetch bounded pages, not a guessed stream cursor. Reconnection always refreshes the current view.

The `/api/live` stream sends `change` events with `{ version: 1, ids: string[] }`. A nonempty `ids` list identifies affected recordings; an empty list means **invalidate the entire current view**, not "nothing changed." Connection/reconnection sends a broad invalidation. If a slow consumer already has an unsent change, another change deliberately broadens that pending event to an empty `ids` list, bounding queued metadata rather than retaining an ever-growing ID set. Once broad, the pending invalidation cannot narrow again. Selective consumers must always support the empty-list convention.

Separate `indexing` events carry the latest phase and recording-file counts. They update status only, without invalidating library data; under backpressure the newest progress snapshot replaces older unsent progress.

Full-text queries are parameterized. Indexing is independent of `history.jsonl`; session identity includes its source file so duplicate IDs across copied directories do not collide. Unknown event types remain available through the activity filter and raw record disclosure. `recordPolicy` in `src/shared/records.ts` files every record type Claude Code 2.1.302 writes as transcript, bookkeeping, or state, the way Claude Code's own pruner does except for `progress`, which the pruner files as boundary-cleared but older versions wrote beside the conversation, so the table reads it as transcript; a record whose type, or whose `system` or `attachment` subtype, this build does not know is counted on its recording and named in the catalog, so the sidebar's index status can say that a different Claude Code version may have changed its recording format. An `api-request-blob` record holds a message Claude Code sent to the API. It indexes as a system record with no blocks, so it never takes a tool link or tool count from the record it copies, and its searchable text keeps only the context composed for the request, leaving out the assistant turns, tool blocks, and reasoning that repeat other records and the text a user or attachment record holds, such as the prompt that a copy of the message sent for it repeats, even when Claude Code writes that record after the copy. Claude Code's own bookkeeping and session state records, the types `recordPolicy` files as `bookkeeping` or `state` other than the API request records, such as `last-prompt`, `file-history-snapshot`, `atis-latch`, `queue-operation`, `cost-state`, `permission-mode`, and `summary`, also index as system records with no blocks; the prompt copies in `last-prompt.lastPrompt` and `queue-operation.content` are left out of their searchable text because a user record holds the prompt, while the rest of each record stays searchable. An `assistant` record whose `message.model` is `<synthetic>` is Claude Code's own stand-in for a model turn: the record it writes when an API request fails for good (`isApiErrorMessage: true`, with the error kind in `error`, a cause code in `apiError`, and the HTTP status in `apiErrorStatus`), or a note such as `No response requested.`. It indexes with the `synthetic` category, so it never counts as a message or a response, and an API error sets the error flag. The interruption marker Claude Code writes as a `user` record when a turn is interrupted, whose only content is `[Request interrupted by user]` or `[Request interrupted by user for tool use]`, is its own in the same way and indexes with the same category, so it never counts as a message or a prompt, while a prompt that quotes the marker stays a prompt. Index version 18 re-indexes the recordings holding the interruption marker and version 19 those holding a message copy with searchable text; finding them reads every event, so both run with the first scan rather than on open, as did versions 8, 10, and 11, which once found the recordings an earlier build read differently for `api-request-blob`, session state, and `<synthetic>` assistant records until version 15 stood in for versions 8 to 15 and re-read every recording below it. Session titles follow Claude Code's own `--resume` picker: an agent name, else a custom title, else an AI title, else a summary an older version wrote, each the latest of its kind, else the first prompt by Claude Code's first-prompt rules, so the slash command, local command output, hook, interruption, and IDE context records it skips never title a recording. `sessions.named` keeps the rank of the explicit title's kind, so a later title of a lower kind never replaces it. Index version 17 retitles recordings holding an agent name or summary or titled explicitly by reading their stored records at the first scan, without re-reading the recordings, as version 9 once did for recordings an earlier build titled from such a record before the collapse into version 15. A `tool_result` Claude Code marked `is_error` because a decision stopped the tool, whether the user, a permission rule, a safety check, a PreToolUse hook, or the auto mode classifier refused it or it was interrupted or cancelled, is recognized by the `toolDenialKind` Claude Code 2.1.30x files beside it, or else by Claude Code's own recorded message (`src/shared/decisions.ts`), and indexed as a decision rather than an error; `normalize()` copies the record's kind onto the result, so a result stored apart from its record keeps it, and files a user rejection the session's shutdown cut short as an interruption, as Claude Code does when it loads one. The Errors view shows it under its own label, while error counts, the **With errors** filter, the error ordering, and the activity strip's error bars cover failures only, among them tool failures, error-level records, and the assistant records Claude Code marks `isApiErrorMessage`, but not the error-level `api_error` banner Claude Code streams to its UI while it retries a request, which the replay reads as a retry note. `sessions.api_errors` counts the API error turns among the errors and `sessions.decisions` the tool results that record a decision, and the library row's tooltip, the replay's error count, and Session details show both beside the error count; index version 17 fills both from the stored flags without re-reading the recordings. Index version 17 re-reads only the recordings holding a result with a filed kind or a failure whose message it first reads as a decision; version 12 once re-indexed those an earlier build flagged differently, before the collapse into version 15. The last `cost-state` record of a recording also fills `session_costs` with Claude Code's own running total for the session (`totalCostUSD`, `startTime`, `hasUnknownModelCost`, and `modelUsage` keyed by `normalizeModel()` of the requested model string), which the library row, the replay header, the session details, and the usage notes show as **Claude Code recorded** beside the estimate. That total counts the session's subagents and the requests Claude Code bills but never writes to a recording (prompt suggestions, compaction, summaries, memory extraction, hook evaluations), so the estimate from the recorded requests is a lower bound of it and the gap is stated rather than flagged. The same record's `totalAPIDuration` and `totalToolDuration` are kept as measured time, and the `system` records of subtype `turn_duration` that Claude Code writes at the end of each turn are counted and summed on the session row as its active time, the time Claude Code worked as opposed to the recorded span, which counts the pauses between turns; the replay shows each as a timestamped note with its duration. `thinkingDurationMs` and the API's `thinking_tokens` stay on the raw record and are read when a reasoning card renders. A `relocated` record marks the moment Claude Code moved the session to the project folder of a new working directory, as `EnterWorktree` and `ExitWorktree` do; its `relocatedCwd` serves as the record's working directory, so the replay marks the move where it happened. Index versions 13, 14, and 15 once re-indexed only the recordings holding a `cost-state`, `turn_duration`, or `relocated` record; version 15 now marks every recording for re-reading at the first scan and stands for versions 8 to 15, whose per-version predicates over the stored events were collapsed once no released index sat between 7 and 17, so an index below 15 pays one full re-read instead. The scan recognises the move itself: a new file whose path inside its project folder matches a known recording whose old path is confirmed gone keeps that recording's row, so its id, bookmark, replay links, and read position survive a worktree session and the return from it. The `version` Claude Code writes on its records fills `sessions.version` and a `version` facet, which the library filters by and the replay header shows. Index version 16 fills it and the unrecognized record counts from the stored records at the first scan, without re-reading the recordings, and re-reads only those holding a record of a type it first reads as a note whose content an earlier build indexed, or a record SQLite's JSON parser rejects. Versions 16 and 17 fill one recording at a time and yield to the event loop between batches of that work, so the server, already bound, keeps answering while a large index upgrades.

The index tracks filesystem identity and prefix/tail checkpoints, maintains separate tool-result and tool-call lookups, and repairs interrupted imports at startup. Schema versioning invalidates derived records when normalization changes. Both the source and state paths are resolved through existing directory links before enforcing their separation. See [SQLite index schema](sqlite-schema.md) for the tables, columns, and schema versions.

## UI runtime

Solid `2.0.0-rc.9` and `@solidjs/web` are pinned together. The official Solid 2 migration and DOM documentation in the `solidjs/solid` repository defines the implementation: split compute/apply effects, `onSettled`, renderer-owned JSX types, and keyed list reconciliation. The matching `@solidjs/vite-plugin` is pinned. Vite performs the Solid compiler transform; Bun runs development, production, scripts, and tests. No Solid 1 compatibility UI packages are needed.

## Responsive workspace

Discovery uses one chronological list at every viewport, bounded to 1600px on wide displays. Archive totals are a compact definition list beside the landing hero, hidden with it while searching, filtering, viewing a workspace, or replaying, and on desktop displays 820px and shorter, where the heading becomes "Session library". The expanded Usage breakdown is the recording list's first full-width grid item, so it scrolls with the rows and the list keeps its height. Workspace grouping has one persistent entry in the sidebar section heading. Replay fills the available workspace, and prose wraps to the full conversation width unless the reader opts into a measure: the sidebar's Reading width selector holds paragraphs, lists, blockquotes, and headings inside `.md-content` to about 80 characters per line in Comfortable mode, while code fences, tables, tool cards, and diffs keep the full width in both modes. Single source newlines in Markdown prose render as whitespace; paragraphs, explicit Markdown hard breaks, and code formatting remain intact. Code, diffs, tables, and tool output retain their existing width and overflow behavior. The session library can be hidden or resized by dragging its divider or using arrow keys, Home, and End; double-clicking restores its responsive default. Global search reveals a hidden library. A separately collapsible metadata and event-outline rail appears when the replay container has enough horizontal room. Height queries reduce chrome on short laptop displays. Mobile navigation is inert while hidden, with managed keyboard focus when open. The discovery filter menu is anchored to its control rather than the document flow: it stays inside the viewport horizontally, is capped to the space below its summary and flips above it when that space runs short, so its reset action stays reachable by internal scrolling, and becomes a bottom sheet with an explicit close control on phone widths.

Typography uses shared, rem-based roles: 14px controls and code, 12px metadata, 13px supporting text, and the existing 15px/1.65 conversation rhythm at the browser's default font size. Compact layouts retain the same role sizes rather than shrinking utility text. The sidebar's Text size selector offers a larger scale across discovery and replay, and the Reading width selector below it chooses between the full pane and a roughly 80-character measure that scales with the chosen text size. Both are saved locally in the browser, with an in-memory fallback when storage is unavailable; the saved reading width is applied to the document element before the application bundle runs and follows changes made in another tab, and an invalid or missing value falls back to the full width. Browser font preferences and zoom remain independent of these settings.

The replay header prioritizes the session title and close navigation, with copy-resume retained as a quieter secondary action. Event headers establish the first known working directory on each visible page and show subsequent changes; repeated identical paths are omitted from the header but remain in each raw event. Filtering and paging re-establish the visible source context. Raw event disclosures use muted metadata styling while preserving keyboard access and 44px phone hit areas. Code panels that show recorded JSON, including payloads embedded in otherwise plain record text, highlight each complete payload token by token in the client with a strict, bounded scanner; nothing is parsed into objects, oversized values stay plain, and search marks compose with the token spans. A one-line provenance strip under the title shows the folder leaf, branch, first to last recorded span, and model at every pane width, followed on a replay pane wider than 960px by the Claude Code version that wrote the recording when its records name one, truncating the folder first, and a bookmark toggle sits beside the title in the same place at every width. A keyboard-accessible Details disclosure holds the full title, original workspace, branch, model, Claude Code version, activity counts, provenance, and the export action without reducing the transcript viewport when open. Long titles take at most two header lines; their full text remains available in Details. Tabs and in-recording search share a row when the replay pane is wide enough, and stack on compact panes without reducing text size.

The client requests 50 recordings or 60 events at a time. Each events page also carries `results`, the recorded result of every call on it, and `calls`, the tool name and capped top-level text inputs of the call behind every result on it. Conversation and Tools fold a result into its call's card when both are on the page, and every view folds an unbroken run of `api-request-blob` message copies into the `api-request` record directly after it; a bookkeeping or state record reads as a one-line **Bookkeeping** or **Session state** note naming its type, labelled "No timestamp" when Claude Code wrote none, with its own searchable text shown only when a highlighted term is in it; a result shown on its own, as on the Errors tab, uses `calls` to name the command that failed without the server shipping the call's whole event. A recording's activity strip comes from `/api/sessions/:id/timeline`, which takes the replay filters and returns per-minute buckets (coarsened to 10 minutes, hours, or days past 1500) carrying every record's count plus the matching records' count, error count, and first and last page offsets. Offsets come from the same ordering as the events endpoint, so choosing a bucket opens a page without translating time back into a position; undated records ride with the latest earlier timestamp. Find stepping uses `/api/sessions/:id/matches`, which takes the same replay filters plus a `find` term and returns up to 5000 matching records in order, each with its page position, sequence, and event id, along with the full match count; stepping to a match on another page requests the page at that position. The unfiltered layout is cached per recording size, and the client lays out bins and idle breaks for the strip's measured width. The overview rail's Files changed view comes from `/api/sessions/:id/summary`, computed on demand from the existing event, tool-call, and tool-result tables with no schema change: Edit, Write, MultiEdit, NotebookEdit, and Read inputs are read one record at a time, relative paths resolve against each record's working directory in that path's own Windows or POSIX style, and files group under the recorded working directories plus the directories a recorded `/add-dir` output says were added. A changed file outside every folder is listed under Scratchpads when its path has the whole shape of Claude Code's per-session scratchpad directory (`…/claude[-<uid>]/<project>/<session id>/scratchpad/`), otherwise under Other locations. The grouping is cached per recording size; each request adds every referenced record's position under the same replay filters as `/matches`, or null when those filters hide it, and the client opens hidden records in All events with their context. Tool bodies and raw records mount on demand. Stable event identities preserve open disclosures across metadata refreshes, and request sequence guards prevent stale fetches from replacing a newer page.

## Implementation layers

### Optional desktop runtime

`src-tauri` is a deliberately thin Tauri 2 host. `scripts/build-sidecar.ts` first builds the normal Vite client, then uses `bun build --compile` to create a target-specific `claude-blackbox-server` sidecar with `dist/` embedded. Tauri reserves a free loopback port, starts that binary with the existing `--port` option, waits for the listener, and creates the main webview at the resulting `http://127.0.0.1:<port>` origin. No recorder, SQLite, HTTP, or client behavior is reimplemented in Rust.

The localhost and desktop entry points therefore share the same server and security boundary. The desktop host exposes no Tauri command APIs to the remote-origin page, restricts navigation to its selected loopback origin, and terminates the sidecar when the main window closes. This retains the operational tradeoff of a listening TCP socket and packages the Bun runtime in every desktop artifact.

1. Typed application foundation and pinned toolchain.
2. Lossless ingestion and searchable local index.
3. Loopback API, live invalidation, and reversible preferences.
4. Session discovery shell and structured replay.
5. Workspace grouping, focused search, and usability refinements.
6. Edge validation, regression coverage, and operating documentation.
